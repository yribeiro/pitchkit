# PitchKit

React-first football pitch visualisation library: mplsoccer for the web. Say "React-first"
in user-facing copy, never "React-native", which reads as the mobile framework.

## Repo layout

npm workspaces + Turborepo, Node >= 22.

| Path                      | What it is                                                               |
| ------------------------- | ------------------------------------------------------------------------ |
| `packages/core`           | Coordinates, geometry, scene model, Canvas painters. No React, no deps.  |
| `packages/react`          | The React components, and the bundled Agent Skill in `skills/pitchkit/`. |
| `packages/data-providers` | StatsBomb, SkillCorner and Wyscout open-data loaders.                    |
| `apps/docs`               | pitchkitjs.com: Next.js, Fumadocs, Tailwind v4.                          |
| `examples/*`              | Vite and Next.js review apps.                                            |

```bash
npm run build      # must run before typecheck on a fresh checkout
npm test
npm run typecheck
npm run lint
npm run format
```

## Rules

**Architecture**

- Shared maths lives in `@pitchkit/core`. When `react` needs logic a core painter has,
  extract it into a pure exported function in `core` and call it from both (D2).
- `@pitchkit/react` is the only supported rendering surface. New marks ship React-only; don't
  add to core's SVG painters (D3).
- Theming is CSS variables only. No JS theme objects, and `appearance` never carries colour
  (D8).
- Responsive is the default. Explicit `width` and `height` together are the opt-out (D4).
- Centre-origin handling lives in core via `toExtentFrame`/`fromExtentFrame`. Never add a
  coordinate workaround in a caller. Any module that reasons about a `0..length` box converts
  through the extent frame first (D5).
- Test files derive their pitch-type list from `Object.keys(PITCH_DIMENSIONS)`, never a
  hardcoded list (D6).
- Data loaders keep the provider's own field names and values. Add only lifted coordinates,
  and put interpretation in predicates (D14).
- The dataset facts in
  [architecture: data provider facts](./docs/architecture.md#data-provider-facts) were each
  verified against live data. Re-verify before "correcting" one.

**Changes and releases**

- A change to a published package needs a changeset (`npx changeset`). That includes
  `packages/react/skills/`, which ships in the tarball (D11).
- Adding a pitch type fails `skill-doc.test.ts` until `SKILL.md`'s pitch-type table is
  updated. That's intentional (D12).
- Releases are manual; see [CONTRIBUTING.md: releasing](./CONTRIBUTING.md#releasing). After a
  release, update the release history in `docs/roadmap.md`, and check the root and package
  READMEs against the new versions and dependencies.
- `@pitchkit/data-providers` depends on `csv-parse`, the only third-party runtime dependency
  in any published package. Don't describe the packages as having "zero dependencies".

**Docs site (`apps/docs`)**

- It auto-deploys from `main` via Vercel's GitHub App. There is no deploy workflow or
  `vercel.json`, and deploys don't wait for CI. PRs get preview deployments.
- `components/examples/registry.ts` and `content/docs/api/` are generated by
  `next.config.ts`. If the build fails with `ENOENT … registry.ts`, check `next.config.ts`
  still runs both generators; don't re-chain npm scripts (D18).
- Live examples are standalone `*-basic.tsx` files in `components/examples/`, shown with
  `<PitchPreview name="…" />`. Don't import site-only helpers into them; their source is
  inlined into `llms-full.txt` (D19).
- Write Tailwind class strings out in full. Tailwind doesn't generate interpolated classes.
- When a docs page moves, add permanent redirects for the old URL and its `.md` variant to
  `next.config.ts`.
- `<title>` and the hero `<h1>` differ deliberately; don't make them match (D20). `SITE_URL`
  is the `www` host (D21).
- The PitchKit mark is duplicated across five unlinked files. Read CONTRIBUTING.md's brand
  assets section before touching anything logo-shaped.

## Environment

- On Windows, run `npm`, `node` and `git` inside WSL. A Windows-native `git pull` can leave
  CRLF noise that shows up as a huge diff; see
  [CONTRIBUTING.md: working on Windows](./CONTRIBUTING.md#working-on-windows).
- Dependabot alerts are all in the private `apps/` and `examples/` workspaces; none reach the
  published packages. Keep the docs site's own dependencies current, since it is deployed.
