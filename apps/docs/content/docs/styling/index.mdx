A PitchKit chart has no theme object and no colour props you're required to pass. Two things
set every colour on it, and both are plain CSS:

- **The pitch** — grass, stripes, markings, line weight — reads the `--pitch-*` CSS variables
  (see [Theming](/docs/guides/theming) for the full list).
- **The marks** — `<Scatter>`, `<Arrows>`, `<Comet>` and the rest — take a `className`, so an
  ordinary `fill-*`/`stroke-*` utility colours them.

With Tailwind in the project, four lines of `@utility` make the pitch variables into classes
that read straight from your palette:

```css
/* globals.css */
@utility pitch-surface-* {
  --pitch-surface: --value(--color-*);
}
@utility pitch-stripe-* {
  --pitch-stripe: --value(--color-*);
}
@utility pitch-lines-* {
  --pitch-lines: --value(--color-*);
}
@utility pitch-line-width-* {
  --pitch-line-width: --value(number, [number]);
}
```

After that, a pitch is styled the same way as everything else in your app:

```tsx
<Pitch type="statsbomb" className="pitch-surface-emerald-950 pitch-lines-amber-500">
  <Scatter data={shots} x={(s) => s.x} y={(s) => s.y} className="fill-cyan-300" />
</Pitch>
```

[Configuration → Tailwind](/docs/configuration/tailwind) covers the setup in full, including
the zero-setup `[--pitch-surface:…]` form, and why `className` on a mark only takes effect
once you leave out its `fill`/`stroke` prop.

## One look per provider

The pages in this section each take one data provider and style a typical chart for it,
using data in that provider's **own shape and coordinate system**. The code on each page is
exactly what renders the chart above it, and the looks are starting points to copy.

| Page                                     | Chart                  | Coordinates                                 |
| ---------------------------------------- | ---------------------- | ------------------------------------------- |
| [StatsBomb](/docs/styling/statsbomb)     | Shot map, light report | 120 × 80 yards, origin top-left, y down     |
| [Opta](/docs/styling/opta)               | Pass map, dark board   | 0–100 %, origin bottom-left, y up           |
| [Wyscout](/docs/styling/wyscout)         | Build-up, broadcast    | 0–100 %, origin top-left, y down            |
| [SkillCorner](/docs/styling/skillcorner) | Tracking frame         | Metres from the centre spot, per-match size |

Each look sets its colours with Tailwind classes only. A look you like on StatsBomb data
works on Opta data just by changing `type`, because `type` sets coordinates and the classes
set colour. To load the full matches these samples come from, see [Data](/docs/data).

## Patterns that recur

- **One layer per category.** A class colours a whole layer, so goals vs. misses or complete
  vs. incomplete passes become two layers filtered from the same array. Where the colour has
  to vary continuously per datum (a scale, say), use the `fill` accessor instead — it takes a
  function.
- **`fill-*` on arrows colours the head.** `<Arrows>` puts its `className` on both the shaft
  (a line, coloured by `stroke-*`) and the head (a filled polygon, coloured by `fill-*`), so
  pass both.
- **Variants work.** `hover:`, `dark:`, opacity modifiers like `fill-stone-400/30` — they're
  ordinary Tailwind classes on ordinary SVG elements.
